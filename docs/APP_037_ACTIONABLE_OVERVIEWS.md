# APP 037 — Actionable project, workspace and organisation overviews

Project Overview now starts with the current gated phase and next permitted action. Brief agreement, proposal acceptance, independent internal design sign-off, publication, consultant submissions, formal reviews and design approvals remain separate workflows. Summary actions derive permissions from the existing checked capabilities and identity/independence predicates; they link to the existing workflow screens. Sequential approval slots remain waiting until prior slots approve. Archived projects expose no pending actions.

The screen shows pending decisions, exact accepted brief/proposal revisions, currently shared design versions and their latest visible approval status, compact project/client essentials, and five recent accessible events. Client contact details expand on demand; technical slugs and duplicate metadata are removed. Brief/proposal revision links open the exact accepted revision, including when a newer draft exists. Publishing alone does not count as sharing. External recipients receive their own shared version list, no other recipient names, no private future versions and no internal sign-off activity. Permitted consultants retain their own submission next steps.

Project navigation explains what each section does, including the difference between working design versions, consultant submissions, internal sign-off, assigned reviews, client approvals and issued releases. Existing workflow routes and permission checks are retained. Members without leadership access land on My work and no longer receive a duplicate global Overview destination.

Organisation and workspace homes consume the same project summary RPC. Attention is split into needs your action, waiting on approvers, and team/reviewer next steps. Organisation library submissions appear for organisation administrators. Workspace summaries replace expanded nested project cards; the project portfolio supports search, workspace/phase/attention filters and progressive display. Recent updates include project links. These totals include preparation next steps as well as pending decisions; they are not progress percentages or inferred deadlines.

My work and the global Inbox/bell default to all accessible workspaces in the selected organisation, with an explicit workspace filter. My work covers inherited leadership work even without direct project participation, plus assigned stakeholder decisions. The organisation inbox supports the existing category/priority/source/date filters and tabs with server cursor pagination. Notification reads and mutations remain recipient-scoped; mark-all-read delegates to the existing checked workspace RPC for each eligible workspace. Existing workspace inbox URLs remain available. Notification invalidation includes organisation feeds and badges.

Migration `20261115010000_app_037_actionable_overviews.sql` adds four checked functions; no table, workflow state, RLS, sharing policy, storage URL or decision semantics change. Summary reads use APP 036 visibility predicates/security-barrier views. Hub queries execute within the database rather than making one browser request per project. Portfolio display is progressively capped, but the hub currently returns all accessible project summaries; server pagination is a future scaling improvement.

Validation: `tests/access/actionable-overviews.mjs` exercises real brief/proposal/sign-off/publication/share/approval RPCs, role-specific actions, sequential slots, exact revisions, private future versions, organisation/workspace isolation, inbox cursor and recipient-scoped mark-read. `tests/access/actionable-overviews-browser.mjs` checks owner/lead/contributor/client/viewer navigation, accepted-revision links, organisation feeds/workspace filtering, desktop/mobile overflow and the mobile drawer. All fixtures are local. Production smoke is read-only.
