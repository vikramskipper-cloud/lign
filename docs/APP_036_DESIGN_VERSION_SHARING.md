# APP 036 — Internal sign-off and exact-version client access

Design versions now require an explicit internal review before publication or client sharing. A different project lead or inherited workspace/organisation leader must sign off; contributors cannot substitute for leadership, and creators or attached-file uploaders cannot sign off their own work. Submission freezes version labels, notes and file attachments. Changes requested reopen ordinary draft editing; approved published work requires a new version for further content changes. Consultant submissions retain their existing revision/history flow, with leadership-only acceptance creating the same internal sign-off record.

`design_version_shares` grants one version to one active project participant. Shares can be reserved for pending project invitations and take effect when the intended stakeholder activates. Publishing alone grants no external access. Sending an approval or opening an external review shares only its approved target with the assigned recipients. Leadership can share explicitly with reviewers, approvers or viewers, and revoke access. New versions inherit no shares. Removing a participant or revoking their relevant membership invalidates access. Revocation blocks new API reads and new signed-link issuance. Previously issued storage links retain their original expiry, and downloaded material cannot be recalled.

Working access is retained for active internal leads/contributors and inherited leadership. External users can read exact shared, internally approved versions plus their own permitted consultant submissions. Raw table RLS, storage downloads, version/file direct links, review/approval detail and history, dashboards, requirement traces, notifications and private presence channels enforce this boundary. Unshared internal release/evidence bundles remain internal. Existing versions receive no invented sign-off or automatic blanket shares: leadership must review and explicitly share legacy material before external access.

Comments, annotations, changes and decisions default to internal visibility for the internal team. The design viewer offers an explicit client-visible mode for new comments and annotations; replies follow their parent thread. External feedback is shared within the permitted target. Internal comment edit history and internal activity remain private. Proposal draft access remains internal, reviewed proposal revisions are limited to the named approver, and internal review notes are masked. A proposal creator cannot perform its internal leadership review.

The project Designs screen and workspace Reviews screen expose a scoped internal sign-off queue. Submission routes in-app notifications to eligible project leads, falling back to workspace or organisation leadership. Draft approval requests no longer generate external notifications; the external approval notification is generated when the request is sent. No external email delivery integration is introduced.

Checked read RPCs use security-barrier views with explicit object predicates; clients cannot query those views directly. The schema inventory/provenance audit now includes views and the LIGN presence policies. The approval detail query's pre-existing JSON conversion and aggregation errors were corrected while exercising client decisions. Authentication changes clear cached data when the user identity changes, including activation links opened while another account is signed in.
