# APP 038 — Project creation to Gather needs

Project creation continues to open Project brief directly. The first tab now starts with compact project/client/lead context and three questions: objective, deliverables and scope. Scope remains recommended; the existing backend still requires objective and deliverables for review. Audience, budget, timing, success criteria and organisation discipline questions remain available under expandable project details. Saved revisions and read-only briefs show those additional questions expanded. Existing question customisation remains available below the main task.

A preparation checklist explains the existing agreement requirements: objectives/deliverables, a requirement or preference with acceptance checks, resolved questions, active responsible team members and a selected approver whose invitation is accepted. It is guidance, not a replacement for the existing checked agreement RPC. Spaces/zones and references remain optional. Leadership can explicitly choose the sole existing project approver from a suggestion; the choice is saved with the draft, never applied automatically.

Save draft is consistently named from the first save onward. A live status distinguishes unsaved changes from saved work. Save and continue to requirements persists the draft before changing tabs, with duplicate-save protection; errors and optimistic-lock conflicts retain local edits on Gather needs. Draft saving remains manual and permits incomplete work. Existing unsaved-navigation guards, immutable revisions and role restrictions are retained. Historical/read-only work can continue through the tabs without a save. Empty history selectors are hidden, and clarification notes are collapsed on Gather needs while remaining expanded on the other steps.

Creation copy now describes inherited discipline questions and copyable invitation links, without suggesting an email was queued. This release does not introduce email delivery, change project access, or change the requirements/references/agreement workflows. No database migration is needed.

Verification: `tests/access/brief-start-browser.mjs` exercises actual creation, initial context, three essential fields, preserved optional answers, explicit respondent choice, persistence before continuation, failed/stale-save preservation, mobile layout and viewer restrictions. The existing full brief browser journey checks discipline questions, client contributions, references, team review and exact-revision agreement. All test fixtures are local; production smoke is read-only.

Historical gap found during repeat verification (resolved by APP 039): creating another project with the same external client can hit `invitations_active_key` while that client's workspace invitation is pending. APP 038 left invitation lifecycle semantics unchanged. APP 039 unifies invitation reuse across project creation and Team & access.
