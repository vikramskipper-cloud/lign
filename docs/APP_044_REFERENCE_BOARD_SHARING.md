# APP 044 — Private reference preparation and client input

Project References has three stages: **Team preparation**, **Client input**, and **Brief direction**. New reference boards and approved Library imports start privately. Internal organisation members with project access can read them; existing project contribution/edit capabilities still control writes. Project leadership explicitly shares a board for collaboration and can copy its authenticated review link. A shared board is a live project space: its references and later additions are visible to project participants. Sharing is one-way in this slice. Existing boards remain shared, preserving the access clients already had.

Clients and other project contributors can open a bounded, shared Client suggestions board using Add your references, even before a team board has been shared. Creation checks contribution access, locks the project, and reuses one active input board under a partial unique index. Read-only viewers cannot create boards or contribute. Only project leadership creates ordinary preparation boards, shares them, and selects references for brief agreement. Likes/shortlists remain preferences rather than design approval.

Private preparation comments/preferences are marked internal when saved. They remain internal after the board is shared. New optional `p_internal` tail parameters preserve the author's intent if another leader shares a board while an internal note is being written; only internal team members can request that audience. Legacy calls use the default and continue working. Direct-table policies and feedback read RPCs filter internal feedback; immutable reference snapshots always omit it. Private event payloads are redacted so preference text and import metadata cannot leak through project activity.

Private visibility is checked in board/card/comment getters, card creation/editing, feedback writes, raw-table RLS and planning-file reads. Library imports defer file publication until board sharing; existing Library project-publication records retain their established access. Shared reference-file identities remain readable for historical packages, including shared template copies. Proposed design documents and brief selection snapshots accept only shared references. Existing proposal-file permissions and independent leadership/client approval remain in place.

The Brief References step shows visible progress, links to the reference workflow and saves before continuing to Review & agree. Historical/awaiting-agreement snapshots still use their immutable references. Additional links and files stored directly on the brief are explicitly labelled visible to project participants; private preparation belongs in reference boards.

Reference editors, comments, preference notes and uploads participate in a navigation/unload guard. Sharing is disabled while local reference edits or saves/uploads are pending. New reference form drafts can be cleared; existing editors retain their reload controls. Board layout choices retain legacy stored types, with visual boards using columns and reference lists using rows. Existing reusable templates can still be copied; new Library reusable resources remain organisation collections.
